# Требования

**Статус документа:** черновик.
**Обозначения приоритетов:** Must — без этого продукт не работает; Should — важно, можно отложить на второй релиз; Could — желательно.
**Обозначение зависимости:** `[зависит от RQ-n]` — требование не может быть реализовано или проверено до ответа на вопрос RQ-n из `telegram-api-research.md`.

---

## 1. Область

Документ описывает требования к Telegram Reader — Mini App для превращения текстовых постов выбранных пользователем Telegram-каналов в аудио.

Вне области документа: архитектура реализации, выбор технологий, схема данных, API-контракты.

---

## 2. Термины

| Термин | Значение |
| --- | --- |
| Reader | Приложение Telegram Reader |
| Mini App | Приложение, запускаемое внутри Telegram |
| Канал | Telegram-канал, добавленный пользователем в Reader |
| Пост | Одно сообщение канала |
| Текстовый пост | Пост, содержащий текст. Посты с медиа и иными вложениями не считаются текстовыми |
| Новый пост | Пост канала, который пользователь ещё не прослушал в Reader |
| Состояние прослушивания | Собственное состояние Reader: какие посты прослушаны и на каком месте остановлено воспроизведение |
| Reference канала | Идентификатор канала, полученный от Telegram при выборе канала пользователем |

---

## 3. Пользователи и роли

| Роль | Описание |
| --- | --- |
| Пользователь | Единственная роль. Владеет своим списком каналов и своим состоянием прослушивания |
| Администратор сервиса | Эксплуатация сервиса. Доступа к содержимому постов пользователей не имеет |

Многопользовательские роли, шаринг списков каналов и публичные подборки не предусмотрены.

## 4. Функциональные требования

### 4.1. Запуск и аутентификация

| ID | Требование | Приоритет |
| --- | --- | --- |
| FR-AUTH-01 | Reader запускается как Mini App внутри Telegram | Must |
| FR-AUTH-02 | Reader идентифицирует пользователя по данным, переданным Telegram при запуске | Must |
| FR-AUTH-03 | Reader проверяет подлинность переданных данных на своей стороне перед любым использованием | Must |
| FR-AUTH-04 | Reader отклоняет запросы с неподтверждёнными или устаревшими данными аутентификации | Must |
| FR-AUTH-05 | Reader не запрашивает у пользователя номер телефона, контакты, доступ к личным сообщениям и список чатов | Must |
| FR-AUTH-06 | Reader работает без регистрации отдельного аккаунта: учётная запись создаётся автоматически при первом запуске | Should |

Детали проверки подлинности — в `security.md`, §6.

### 4.2. Добавление канала

| ID | Требование | Приоритет |
| --- | --- | --- |
| FR-CH-01 | Пользователь добавляет канал нажатием «+ Хочу слушать» | Must |
| FR-CH-02 | Выбор канала происходит в интерфейсе Telegram, предоставленном платформой | Must |
| FR-CH-03 | Reader не получает список подписок пользователя, не сканирует чаты и не добавляет каналы автоматически | Must |
| FR-CH-04 | После выбора канала Reader получает его reference и сохраняет канал в список пользователя | Must |
| FR-CH-05 | Один и тот же канал не может быть добавлен дважды | Must |
| FR-CH-06 | Пользователь может удалить канал из списка | Must |
| FR-CH-07 | После удаления канала Reader прекращает обработку его контента | Must |
| FR-CH-08 | Reader сообщает пользователю результат добавления: канал добавлен или канал добавлен без доступа к постам | Must `[зависит от RQ-1, RQ-3, RQ-4]` |

## 8. Критерии приёмки первого релиза

1. Пользователь открывает Mini App и видит пустой список каналов.
2. Пользователь добавляет канал через интерфейс Telegram.
3. Канал появляется в списке с названием, количеством новых постов и состоянием прослушивания.
4. Пользователь открывает канал и видит посты, включая уже прослушанные.
5. Пользователь выбирает пост и слышит его озвучивание.
6. После прослушивания пост помечается как прослушанный, счётчик новых постов уменьшается.
7. Состояние сохраняется после перезапуска Mini App.
8. Пользователь удаляет канал, и его контент больше не обрабатывается.
9. Не нарушен ни один пункт BAN-01…BAN-18; выполнены SEC-REQ-01…SEC-REQ-07, SEC-AUTH-01…SEC-AUTH-07, SEC-DATA-01…SEC-DATA-08.
10. Для каналов, контент которых недоступен, поведение соответствует FR-LIST-06.
