# TTS: синтез речи в PoC

Документ описывает, как в PoC устроен Text-to-Speech: какой провайдер выбран, где лежит ключ,
какие ограничения и как заменить провайдера.

> **Текущее состояние: провайдер не подключён** (`TTS_PROVIDER=none`). Код синтеза написан и готов,
> но выключен: `POST /api/posts/:id/audio` отвечает `{"status":"not_implemented"}`, никакие внешние
> API не вызываются, ключи не нужны. Включается одной переменной — см. §1 и §8.

## 1. Выбранный провайдер

**OpenAI-совместимый `POST {TTS_BASE_URL}/audio/speech`** (по умолчанию `https://api.openai.com/v1`,
модель `tts-1`, голос `alloy`). Пока он не включён: `TTS_PROVIDER=none`.

Почему именно он, когда придёт время подключать:

- один HTTP-запрос, никакого SDK — в проекте нет лишних зависимостей;
- интерфейс стал отраслевым стандартом: тот же путь и тело запроса используют другие провайдеры,
  поэтому смена провайдера сводится к смене `TTS_BASE_URL` и `TTS_MODEL`;
- принимает русский текст, отдаёт готовый MP3, который играет webview Telegram и на iOS, и на Android;
- не требует ни voice cloning, ни стриминга, ни настройки проекта в облаке — только ключ.

Второй провайдер `macos-say` (`say` из macOS) добавлен не как продуктовый вариант, а чтобы весь
pipeline можно было проверить без ключа: он синтезирует тот же текст локально и возвращает m4a.
Он работает только на macOS и в деплое бесполезен.

Текущее поведение при `TTS_PROVIDER=none`:

```
POST /api/posts/:id/audio
{ "id": "…", "status": "not_implemented", "provider": null, "audioUrl": null, "audioUrls": [],
  "message": "Провайдер TTS не подключён (TTS_PROVIDER=none), поэтому аудио ещё не создаётся…" }
```

Mini App на такой ответ не показывает ошибку: состояние `AUDIO_NOT_CONNECTED`, кнопка Play
остаётся заблокированной, а пост виден. Включение провайдера меняет ответ на:

```
POST /api/posts/:id/audio
{ "id": "…", "status": "ready", "provider": "openai", "chunks": 1, "cached": false,
  "audioUrl": "https://…/api/posts/<id>/audio", "audioUrls": ["…"] }
```

## 2. API

| Что | Значение |
| --- | --- |
| Method / path | `POST {TTS_BASE_URL}/audio/speech` |
| Auth | `Authorization: Bearer $TTS_API_KEY` |
| Тело | `{ "model": "tts-1", "input": "<текст>", "voice": "alloy", "response_format": "mp3" }` |
| Ответ | бинарный аудиофайл (`audio/mpeg` для mp3) |
| Ошибки | JSON `{"error":{"message":"…"}}`, сервер прокидывает текст ошибки в Mini App |

Голоса `tts-1`: `alloy`, `echo`, `fable`, `onyx`, `nova`, `shimmer`. В PoC голос фиксирован
переменной `TTS_VOICE`, выбора голоса в интерфейсе нет.

## 3. Стоимость

`tts-1` — **$15 за 1 млн символов** (примерно $0.015 за 1000 символов; `tts-1-hd` — $30).
Тарифицируются именно символы входного текста.

Ориентир для PoC: пост на 4096 символов (потолок одного запроса) — около **$0.06**. Типичный
пост канала на 1000–1500 символов — около $0.02. Аудио кэшируется по `post id`, поэтому повторное
открытие Mini App ничего не стоит.

Актуальные цены стоит сверять на странице тарифов провайдера: они меняются.

## 4. Ограничения

| Ограничение | Что делает PoC |
| --- | --- |
| Не более **4096 символов** в одном запросе | Текст режется на части по предложениям; части синтезируются по очереди и проигрываются подряд (см. §5) |
| Только текст | Картинки, видео, стикеры, опросы не обрабатываются. Эмодзи остаются в тексте: провайдер их игнорирует сам, а очищать текст в PoC незачем — так видно, что озвучивается ровно тот пост, который пришёл |
| Нет стриминга | Аудио приходит целиком, поэтому есть пауза на синтез (обычно 1–3 с на короткий пост) |
| Задержка первого запроса | Mini App показывает состояние «Подготавливаем аудио…» |
| Файловая система Vercel эфемерна | Кэш аудио живёт на диске backend. При деплое backend на Vercel нужен внешний storage (см. §7) |

## 5. Длинный текст: части вместо обрезки

`TTS_MAX_CHARS` (по умолчанию 4096) — это лимит одной части. Текст длиннее лимита режется в
`splitText()` по границам предложений; предложение длиннее лимита делится по словам, слово —
по символам. Текст не обрезается и не теряется молча.

Сервер синтезирует каждую часть отдельным запросом и складывает файлы рядом:

```
<AUDIO_CACHE_DIR>/<postId>/chunk-000.mp3
                          /chunk-001.mp3
                          /manifest.json
```

Mini App получает список `audioUrls` и играет части последовательно одним и тем же `<audio>`:
после события `ended` подставляется следующая часть, прогресс идёт по текущей части, в интерфейсе
видно «часть 2/3». Когда пост доигран, плеер возвращается к первой части, и следующее нажатие
Play читает пост сначала.

## 6. Где хранится ключ

- `TTS_API_KEY` читается только в `server/src/tts.js` через `process.env`.
- Ключ не попадает ни в `app/`, ни в собранный бандл (Vite подставляет во фронтенд только
  переменные с префиксом `VITE_`).
- Ключ не печатается в консоль: `describeTts()` сообщает только факт «TTS_API_KEY найден».
- Тексты ошибок от провайдера проходят через `makeKeyScrubber()` — если ключ окажется внутри
  сообщения об ошибке, он будет заменён на `<TTS_API_KEY>`.
- `.env` в `.gitignore`; в репозиторий попадает только `.env.example` без значений.

Переменные:

```dotenv
TTS_PROVIDER=none       # none (провайдер не подключён) | openai | macos-say
TTS_API_KEY=            # ключ провайдера, только на backend
TTS_BASE_URL=https://api.openai.com/v1
TTS_MODEL=tts-1
TTS_VOICE=alloy
TTS_MAX_CHARS=4096
```

При `TTS_PROVIDER=none` значение `TTS_API_KEY` не читается вообще: сервер не выходит в сеть.

## 7. Где хранится аудио

Файлы лежат в `<AUDIO_CACHE_DIR>` (по умолчанию `server/.audio-cache`, каталог в `.gitignore`).
Это самый простой вариант для PoC: backend сейчас работает локально, а `GET /api/posts/:id/audio`
отдаёт файл с диска с поддержкой `Range` (нужно для перемотки в iOS webview).

Ограничение: **на Vercel файловая система эфемерна** — запись работает, но файлы исчезают между
запусками и не разделяются между инстансами. Поэтому при деплое backend на Vercel понадобится
внешнее хранилище (S3, Vercel Blob, Cloudflare R2) — это следующий этап, в PoC не реализовано.

Кэш по `post id`: если аудио для поста уже создано, повторный `POST …/audio` вернёт `cached: true`
и не обратится к провайдеру. Параллельные запросы на один и тот же пост ждут один синтез
(`generateOnce`), а не платят дважды.

## 8. Как заменить провайдера

**Выключенный провайдер → включённый.** Меняется одна переменная в `.env` и перезапускается
сервер. Больше ничего править не нужно: endpoint, кэш, состояния Mini App уже рассчитаны на оба
ответа (`not_implemented` и `ready`).

```dotenv
TTS_PROVIDER=macos-say   # проверить pipeline локально, без ключа и без сети
TTS_PROVIDER=openai      # боевой вариант, нужен TTS_API_KEY
```

**Другой OpenAI-совместимый endpoint** — без правок кода:

```dotenv
TTS_PROVIDER=openai
TTS_BASE_URL=https://api.x.ai/v1
TTS_MODEL=<модель TTS из документации провайдера>
TTS_VOICE=ara
```

Так подключается любой сервис с путём `/audio/speech`: и xAI (`api.x.ai`, голоса `ara`, `eve`,
`leo`, `rex`, `sal`), и прокси, и локальные совместимые серверы. Для xAI модель, лимит символов и
поддержку русского нужно сверить в `docs.x.ai`: в этом PoC интеграция проверена только против
контракта OpenAI, живых запросов к xAI не делалось.

**Провайдер с другим протоколом** (Yandex SpeechKit, SaluteSpeech, ElevenLabs) — добавить одну
ветку в `synthesizeChunk()` в `server/src/tts.js`. Функция возвращает
`{ buffer, ext, contentType }`, всё остальное (кэш, chunking, отдача файла, ошибки) работает
без изменений.

## 9. Как проверить TTS без Telegram

Сначала — что endpoint отвечает заглушкой (значение по умолчанию, ключ не нужен):

```bash
cd telegram-reader
TTS_PROVIDER=none API_PORT=3001 node --input-type=module -e "
import { startApi } from './server/src/api.js';
import { savePost } from './server/src/store.js';
const post = savePost('Это тестовый пост для Telegram Reader');
console.log('post id:', post.id);
startApi({ port: 3001 });
"

curl -X POST http://localhost:3001/api/posts/<post id>/audio
# {"status":"not_implemented",…}
```

Затем — реальный синтез. На macOS его можно проверить без ключа и без внешних запросов:

```bash
TTS_PROVIDER=macos-say API_PORT=3001 node --input-type=module -e "
import { startApi } from './server/src/api.js';
import { savePost } from './server/src/store.js';
const post = savePost('Это тестовый пост для Telegram Reader');
console.log('post id:', post.id);
startApi({ port: 3001 });
"

# 2. Синтез (вернёт JSON с audioUrl):
curl -X POST http://localhost:3001/api/posts/<post id>/audio

# 3. Файл:
curl -o /tmp/post.m4a "http://localhost:3001/api/posts/<post id>/audio"
afplay /tmp/post.m4a     # или открыть файл любым плеером

# 4. Повторный POST вернёт "cached": true — второй раз провайдер не вызывается.
```

С провайдером OpenAI порядок тот же, но сначала `TTS_API_KEY` в `.env`, а сами запросы уйдут в сеть.
Запуск `npm run bot` для проверки TTS не нужен: `server/src/api.js` не читает `BOT_TOKEN` и не
обращается к Telegram.

## 10. Что можно улучшить позже

- Внешнее хранилище аудио (обязательно для деплоя backend).
- Стриминг или ранний старт воспроизведения, чтобы не ждать синтез целиком.
- Разные голоса и скорость, выбор языка.
- Отдельное сообщение с готовым аудиофайлом: тогда запись можно слушать средствами самого
  Telegram, независимо от Mini App.
