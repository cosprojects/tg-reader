### Бот (Telegram)
- Меню команд: `/start` «🚀 Запустить», `/reset` «🧹 Сбросить всё», `/help` «❓ Как это работает?».
- Кнопка меню у поля ввода — **Post Reader** (открывает Mini App в один тап).
- Ряд кнопок под полем ввода: «🚀 Старт», «❓ Как это работает?», «🧹 Очистить плейлист» (только когда есть посты), «📮 Связаться» (адрес из `.env`: `SUPPORT_CONTACT=https://t.me/avertino`).
- Клавиатур в сообщениях нет: Telegram запрещает редактировать сообщение с reply-клавиатурой, а статус поста бот обновляет по ходу синтеза.
- Статусы: «✓ Пост добавлен в очередь» → «⏳ Готовим озвучку… часть 2 из 6» → «✓ Озвучка готова».
- Дубликаты: повторная пересылка того же поста не создаёт запись — ключ по каналу и номеру сообщения (`telegramPostKey`), не по тексту.
- Полный сброс `/reset`: посты, очередь, активный синтез и **сообщения бота в чате** (что Telegram даёт удалить, младше 48 часов).
- Медиа без подписи: «Для озвучки нужен текст или подпись к фото/видео», OCR нет.

### Mini App (`app/`)
- Плеер на весь viewport, «дека» управления прижата к низу с учётом safe area; крупные элементы под палец.
- Плейлист: 5 строк, внутренняя прокрутка, состояния ▶ / Ⅱ / ✓ (прослушан).
- Модальное окно редактирования: перетаскивание порядка (Pointer Events, работает в мобильном вебвью), удаление, выбор поста, **«ОЧИСТИТЬ ПЛЕЙЛИСТ» локально**.
- Голос: только МУЖСКОЙ / ЖЕНСКИЙ (пользователь не видит названий моделей), скорость 0.8 / 1.0 / 1.2 через `playbackRate` (без пересборки TTS).
- Очередь подтягивается из `GET /api/queue?userId=…` (при открытии, при возврате, раз в 15 с); записи, которых нет на сервере, убираются — так `/reset` очищает и плейлист.
- При сбое связи плейлист не выкидывается, в шапке плеера видно «НЕТ СВЯЗИ».
- Автопереход на следующий пост, «✓ Пост прослушан» на последнем.

## Текущее окружение

- backend: `npm run bot` из корня, слушает `localhost:3001`, состояние **в памяти процесса** (перезапуск стирает посты и очередь);
- внешний доступ: `ngrok http 3001`, статический домен `https://expulsion-pavestone-patient.ngrok-free.dev`;
- фронтенд: Vercel, прод `https://telegram-reader-eight.vercel.app`, сборка из `app/`;
- кэш аудио: `server/.audio-cache`, ключ «пост + провайдер + голос»;
- TTS: Silero v5_5_ru локально (`.venv-silero`), модель `v5_5_ru`, голос по умолчанию aidar.

## Следующие шаги (то, ради чего нужен нормальный backend)

1. **Постоянное хранилище.** Сейчас посты и очередь живут в памяти: перезапуск backend всё стирает, ссылки в Telegram умирают. Нужна база (Postgres/SQLite) для постов, очереди и состояния прослушивания.
2. **Хостинг вместо ngrok.** ngrok живёт ~18 часов и падает по лимиту; адрес вшивается в фронтенд при сборке — при смене адреса нужен передеплой. Нужен нормальный HTTPS-хост (Vercel для бека, Fly.io, VPS) с постоянным доменом.
3. **Проверка `initData`.** Сейчас `GET /api/queue?userId=…` принимает любой id. Нужна валидация подписи Telegram и получение пользователя из `initData`.
4. **Плейлист на сервере.** Тогда порядок и «прослушано» синхронизируются между устройствами, а «Очистить плейлист» в боте будет чистить его сразу, а не через 15 секунд.
5. **Silero на сервере.** Модель ~100 МБ, грузится в память на каждый синтез (2–4 с на часть). На сервере нужен постоянный диск и, лучше, долгоживущий процесс с загруженной моделью.
6. **Мелкие долги:** решить по `TTS_SILERO_MAX_CHARS` (сейчас 800, работает за счёт повторного деления); даты и время внутри защищённых конструкций модель не читает (нужен слой дат); таймлайн показывает текущую часть, а не сумму по посту.

## Как запускать

```
cd /Users/kirillnevzorov/Documents/GitHub/tg-reader/telegram-reader
npm run bot                          # backend + бот (long polling)
npm run dev                          # фронтенд на 5173
ngrok http 3001                      # внешний доступ для Mini App
npm run build                        # сборка фронтенда
cd app && npx vercel deploy --prod --yes --scope cosprojects-projects   # деплой (--scope обязателен)
```

Перед запуском backend проверить, что порт 3001 свободен: `lsof -nP -iTCP:3001 -sTCP:LISTEN`.
