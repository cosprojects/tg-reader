# Сценарии

**Статус документа:** черновик.
Сценарии описывают поведение продукта. Техническая реализуемость сценариев, помеченных `[зависит от RQ-n]`, не подтверждена — см. `telegram-api-research.md`.

---

## SC-01. Первый запуск

**Цель:** пользователь попадает в пустой Reader и понимает, что делать дальше.
**Актор:** пользователь, который открыл Mini App впервые.
**Предусловия:** пользователь авторизован в Telegram.
**Связанные требования:** FR-AUTH-01…FR-AUTH-06, FR-LIST-01, FR-CH-01.

**Основной поток:**

1. Пользователь открывает Mini App.
2. Telegram передаёт приложению данные о пользователе.
3. Сервис проверяет подлинность переданных данных и создаёт учётную запись при первом обращении.
4. Пользователь видит пустой список каналов и объяснение, что нужно добавить канал.
5. Пользователь видит кнопку «+ Хочу слушать».

**Исключения:**

- Данные не прошли проверку подлинности или устарели: приложение сообщает, что нужно перезапустить Mini App, и не создаёт учётную запись.
- Сервис недоступен: приложение показывает сообщение об ошибке и возможность повторить.

**Постусловия:** учётная запись существует, список каналов пуст.

## SC-02. Добавление канала

**Цель:** пользователь добавляет канал, который хочет слушать.
**Актор:** пользователь.
**Предусловия:** SC-01 выполнен.
**Связанные требования:** FR-CH-01…FR-CH-11, FR-LIST-06. `[зависит от RQ-1, RQ-3, RQ-4]`

**Основной поток:**

1. Пользователь нажимает «+ Хочу слушать».
2. Открывается предоставленный Telegram интерфейс выбора чата.
3. Пользователь выбирает канал.
4. Telegram передаёт приложению reference выбранного канала.
5. Сервис сохраняет канал в список пользователя, создавая явную запись о разрешении на доступ к этому каналу.
6. Канал появляется в списке каналов.
7. Сервис проверяет, доступен ли контент канала.
8. Если контент доступен — канал отображается как готовый к прослушиванию.

**Исключения:**

- Пользователь закрыл интерфейс выбора, не выбрав канал: ничего не меняется, список остаётся прежним.
- Выбранный канал уже есть в списке: приложение сообщает об этом и не создаёт дубликат (FR-CH-05).
- Контент канала недоступен: канал добавляется, но отображается в списке как недоступный, с пояснением (FR-CH-08, FR-LIST-06). Пользователь видит, что делать дальше. Это ожидаемый исход, а не сбой.
- Пользователь превысил лимит на количество каналов: приложение сообщает об ограничении. Численное значение лимита не определено. **[TBD — needs verification]**

**Постусловия:** канал присутствует в списке; для него существует явная запись о разрешении.

**Замечание о риске.** Шаг 7 — точка, где продукт может столкнуться с ограничением Telegram API. Если доступ к контенту произвольного канала невозможен, сценарий SC-02 выполняется только частично, и «добавление канала» превращается в «добавление канала без контента». Это меняет продуктовую модель и требует решения до начала реализации.

## SC-03. Список каналов

**Цель:** пользователь видит свои каналы и состояние прослушивания.
**Актор:** пользователь.
**Предусловия:** в списке есть хотя бы один канал.
**Связанные требования:** FR-LIST-01…FR-LIST-07.

**Основной поток:**

1. Пользователь открывает Reader.
2. Отображается список каналов.
3. Для каждого канала показаны название, количество новых постов и состояние прослушивания.
4. Пользователь может открыть канал или удалить его.

**Исключения:**

- В списке есть каналы, недоступные для чтения: они отображаются отдельно с пояснением (FR-LIST-06).
- Количество новых постов ещё не рассчитано: отображается состояние загрузки, а не ноль.
- Канал переименован или удалён в Telegram: приложение по-прежнему показывает канал, используя сохранённое название, и помечает его как недоступный.

**Постусловия:** никаких изменений не происходит, кроме действий пользователя.

## SC-04. Просмотр постов канала

**Цель:** пользователь видит все посты канала и выбирает, что слушать.
**Актор:** пользователь.
**Предусловия:** канал добавлен и его контент доступен.
**Связанные требования:** FR-POST-01…FR-POST-08. `[зависит от RQ-1, RQ-2]`

**Основной поток:**

1. Пользователь открывает канал из списка.
2. Загружается список постов канала.
3. Отображаются все доступные посты, включая прослушанные, с признаком прослушивания и фрагментом текста.
4. Пользователь выбирает пост.

**Исключения:**

- Постов нет: отображается пустой экран с пояснением.
- Пост не содержит текста: отображается с пояснением, что озвучивание невозможно (FR-POST-05).
- Контент канала стал недоступен после добавления: отображается сообщение об отсутствии доступа вместо пустого списка.
- Список очень большой: применяется постраничная загрузка.

**Постусловия:** ни один пост не помечается прослушанным только от просмотра.

## SC-05. Прослушивание поста

**Цель:** пользователь слышит текст выбранного поста.
**Актор:** пользователь.
**Предусловия:** SC-04 выполнен, выбран текстовый пост.
**Связанные требования:** FR-PLAY-01…FR-PLAY-10, FR-CONT-01…FR-CONT-07. `[зависит от RQ-13]`

**Основной поток:**

1. Пользователь выбирает пост и запускает воспроизведение.
2. Сервис извлекает текстовую часть поста.
3. Сервис выполняет синтез речи и возвращает аудио.
4. Аудио воспроизводится в плеере.
5. Пользователь видит, какой пост воспроизводится.
6. По завершении воспроизведения пост помечается как прослушанный.
7. Количество новых постов в списке уменьшается.

**Исключения:**

- Пост не содержит текста: приложение сообщает об этом и не запускает воспроизведение (FR-PLAY-09).
- Синтез завершился ошибкой: приложение сообщает об ошибке и предлагает повторить (FR-PLAY-08).
- Пост слишком длинный: приложение сообщает об ограничении либо озвучивает пост частями. Поведение требует решения (FR-PLAY-07).
- Пользователь прервал воспроизведение: пост не помечается прослушанным; при повторном запуске воспроизведение начинается заново либо продолжается с места остановки — поведение требует решения.
- Пользователь потерял соединение во время воспроизведения: приложение показывает состояние ошибки и позволяет продолжить.

**Постусловия:** пост помечен прослушанным, состояние сохранено.
**Важно:** ни на одном шаге не изменяется состояние прочтения в Telegram (FR-STATE-03, BAN-07).

## SC-06. Продолжение прослушивания в новой сессии

**Цель:** пользователь возвращается и продолжает с того места, где остановился.
**Актор:** пользователь.
**Предусловия:** пользователь уже слушал посты ранее.
**Связанные требования:** FR-STATE-01, FR-STATE-02, FR-STATE-05.

**Основной поток:**

1. Пользователь открывает Reader.
2. Список каналов отображается с актуальным количеством новых постов.
3. Пользователь открывает канал.
4. Отображается список постов с сохранёнными признаками прослушивания.
5. Пользователь может продолжить с первого непрослушанного поста.

**Исключения:**

- Состояние не удалось загрузить: приложение показывает ошибку и не подменяет состояние нулём.
- Пост, на котором остановилось воспроизведение, стал недоступен: приложение предлагает продолжить со следующего.

**Постусловия:** состояние не изменилось, кроме действий пользователя.

## SC-07. Удаление канала

**Цель:** пользователь убирает канал из Reader.
**Актор:** пользователь.
**Предусловия:** канал присутствует в списке.
**Связанные требования:** FR-CH-06, FR-CH-07, SEC-DATA-02.

**Основной поток:**

1. Пользователь выбирает канал и удаляет его.
2. Приложение запрашивает подтверждение.
3. Пользователь подтверждает удаление.
4. Канал исчезает из списка.
5. Запись о разрешении на доступ к каналу аннулируется.
6. Сохранённое состояние прослушивания по этому каналу удаляется.
7. Контент канала больше не обрабатывается.

**Исключения:**

- Пользователь отменил подтверждение: ничего не меняется.

**Постусловия:** канал отсутствует в списке; данных о канале не осталось.
**Важно:** удаление канала в Reader не влияет на подписку пользователя в Telegram.

## SC-08. Канал недоступен

**Цель:** пользователь понимает, почему канала нет в прослушивании, и что можно сделать.
**Актор:** пользователь.
**Предусловия:** канал добавлен, но контент недоступен. `[зависит от RQ-1]`

**Основной поток:**

1. Пользователь открывает такой канал из списка.
2. Приложение объясняет, что доступ к постам этого канала не предоставлен.
3. Приложение объясняет, какие действия со стороны пользователя могут дать доступ, если такие действия существуют.

**Исключения:**

- Никаких действий со стороны пользователя не существует: приложение прямо сообщает, что канал нельзя слушать, и предлагает удалить его из списка.

**Постусловия:** пользователь понимает состояние канала.
**Важно:** приложение не показывает пустой список постов без объяснения и не создаёт видимость, что контент просто не загрузился.

## SC-09. Первый пост до появления доступа

**Цель:** определить, какой объём истории канала доступен пользователю.
**Актор:** пользователь.
**Предусловия:** канал добавлен, доступ появился в момент добавления. `[зависит от RQ-6]`

**Основной поток:**

1. Пользователь открывает канал сразу после добавления.
2. Приложение показывает список постов.
3. Пользователь видит, с какого поста начинается доступная история.

**Исключения:**

- Доступны только посты, опубликованные после добавления канала: приложение объясняет это пользователю.
- Доступна вся история канала: ограничений нет.

**Постусловия:** нет.

## SC-10. Ошибки платформы и лимитов

**Цель:** приложение остаётся работоспособным при ограничениях Telegram.
**Актор:** пользователь.
**Предусловия:** любое состояние.
**Связанные требования:** NFR-COMPAT-03, NFR-REL-01…NFR-REL-04.

**Основной поток:**

1. При очередном обращении к сервису приложение получает ограничение по частоте запросов или ошибку платформы.
2. Приложение сообщает пользователю, что данные временно недоступны.
3. Приложение не показывает устаревшие данные как актуальные.

**Исключения:**

- Ограничение повторяется: приложение объясняет, что следует повторить попытку позже, и не выполняет автоматических повторов в агрессивном режиме.

**Постусловия:** состояние пользователя не повреждено.

## Анти-сценарии

Продукт намеренно не выполняет следующие действия. Эти пункты — не «пока не реализовано», а осознанные ограничения, проверяемые при приёмке.

| ID | Продукт не делает |
| --- | --- |
| AN-01 | Не получает список всех каналов и чатов пользователя |
| AN-02 | Не сканирует чаты и подписки автоматически |
| AN-03 | Не получает личные сообщения |
| AN-04 | Не получает контакты и номер телефона |
| AN-05 | Не отправляет сообщения от имени пользователя |
| AN-06 | Не изменяет состояние прочтения в Telegram |
| AN-07 | Не скачивает медиа-вложения постов |
| AN-08 | Не хранит персональные данные, не необходимые для работы |
| AN-09 | Не получает доступ к каналам, которые пользователь явно не передал приложению |
| AN-10 | Не подключается к аккаунту пользователя через Telegram Business |
| AN-11 | Не собирает контент каналов в базу данных, индекс или поиск |
| AN-12 | Не пересылает и не публикует контент каналов |

Основания: требования брифа и ограничения из `telegram-api-research.md`, §5.

## Сценарии, заблокированные исследованием

| Сценарий | Что блокирует |
| --- | --- |
| SC-02, шаг 7 и 8 | Не подтверждено, что после выбора канала пользователем backend получит доступ к его постам |
